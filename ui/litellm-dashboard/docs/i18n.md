# Dashboard languages

The dashboard uses `i18next` and `react-i18next` with two bundled resources:
`src/i18n/locales/en.json` and `src/i18n/locales/zh-CN.json`

`I18nProvider` initializes each rendered application in English, then restores the
`litellm_ui_language` preference after hydration. It updates the document language
and synchronizes changes across tabs. The language button follows Theme Toggle in
the dashboard header and navbar, and is also available on the login page

## Adding interface copy

Use `useTranslation` from `@/i18n/useTranslation` and add the same semantic key to
both dictionaries. Group keys by feature and keep interpolation parameters equal
across languages. Use complete sentences with named parameters for dynamic copy

Only translate fixed frontend interface text. Keep API response text, errors from
the API, user input, logs, model output, model/provider names, code examples,
JSON keys and protocol identifiers unchanged. Translate option labels without
changing option values, table column IDs, filter values or API payloads

Keep translation calls inside the render path. Pass the hook's `t` into column
factories and include it in memo dependencies when those memos produce labels.
Do not add translation dependencies to request effects or form initialization
that would reset user input. The exported `translate` supplies an English
fallback for standalone helpers; mounted components must pass their reactive `t`

## Scope

The initial rollout covers the shell, login and the currently reachable Virtual
Keys, Models, Usage, Logs, Teams, Internal Users, Response Cache, Router Settings
and Admin Settings views and their shared controls. It preserves customized
hidden tabs and does not translate unused legacy pages

## Validation

No test files were added or modified. The selected 15 existing test files ran
244 passing tests and 18 failing Teams tests. The 18 failing test names match
the results with the original Teams component. Four Header tests also fail with
the original component because they expect controls removed by customization

Browser checks covered language switching, saved preference after reload,
translated login validation and preservation of typed input. Production source
types and bilingual key/interpolation checks are validated separately from the
repository's existing test type errors

Production verification used Node 24, a source-only TypeScript check, and
`next build --webpack --experimental-build-mode compile` followed by
`next build --webpack --experimental-build-mode generate`. All 50 routes were
generated successfully. Both dictionaries have 2,235 matching leaf keys and
matching interpolation parameters
